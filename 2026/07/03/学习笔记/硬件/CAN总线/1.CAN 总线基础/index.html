CAN 总线基础：从 USB2CAN 到达妙电机

最近开始使用达妙 DM-J4310 电机，同时也接触到了 USB 转 CAN 模块、CANH、CANL 和 CAN ID 等概念。

这篇先不深入 CAN 的底层时序，而是从实际设备出发，梳理 CAN 总线在电机控制系统中承担的作用。

整个系统是怎么连接的

目前使用的设备主要包括：

  • 电脑
  • USB2CAN 模块
  • 达妙 DM-J4310 电机
  • 电机电源
  • CAN 通信线

它们之间的关系可以先理解成：

电脑通常不能直接产生 CAN 总线上的电气信号，因此需要 USB2CAN 作为转换设备。

上位机程序先通过 USB 把命令交给 USB2CAN，再由 USB2CAN 将其转换成 CAN 报文并发送到总线上。

CAN 是什么

CAN 的全称是：

中文一般称为控制器局域网。它是一种适合控制器之间交换数据的通信方式，常见于汽车、机器人、工业设备和电机控制系统。

例如，一台机器人中可能同时存在主控制器、多个关节电机、编码器和其他控制器。主控制器需要向电机发送目标位置、速度或力矩，电机也需要返回当前位置、速度、力矩、温度及错误状态。

CAN 总线负责在这些设备之间传递信息。

为什么叫“总线”

CAN 的一个重要特点是，多个设备可以共同连接到同一组通信线路上：

这比给每个电机单独布置一套点对点通信线路更方便，也更适合多关节机器人。

总线上的设备能够看到报文，再根据 CAN ID 和具体通信协议判断这条消息是否与自己有关。

CANH 和 CANL

CAN 通信最核心的两根信号线是：

CANH 和 CANL 并不是一根负责发送、另一根负责接收。它们是一对差分信号线，接收端主要根据两根线之间的电压差判断总线状态：

如果外部干扰同时影响两根线，两者的电压可能一起变化，但它们之间的差值仍可能保持稳定。因此，差分通信在电机和工业现场这类电磁干扰较多的环境中具有较好的抗干扰能力。

CAN 传输的是报文

电脑不会在线路上直接发送“让电机转动”这样的自然语言，而是发送一帧 CAN 报文。

例如：

CAN ID 用来标识消息，DATA 则携带实际内容。至于数据代表位置、速度还是使能命令，需要由设备厂商定义的上层协议解释。

CAN ID 可以先怎么理解

假设总线上有三个电机：

当控制器发送 ID 为 0x02 的报文时，电机 2 可以根据协议识别并执行相应命令。

因此，初学阶段可以暂时把 CAN ID 看作设备编号。不过更准确地说，CAN ID 是消息的标识符，它还可以表达消息类型、控制模式和优先级，不能简单等同于传统设备地址。

电机也会返回数据

CAN 通信通常是双向的：

控制器可以发送目标位置、速度、力矩、Kp 和 Kd 等参数，达妙电机内部的驱动器负责更底层的电流、PWM 和 FOC 控制。

电机执行命令后，还可以通过反馈帧返回：

  • 当前位置
  • 当前速度
  • 当前力矩
  • 温度
  • 错误状态

CAN 和串口的简单区别

串口常见的是 TX 和 RX，点对点连接较多；CAN 使用 CANH 和 CANL，并允许多个节点连接在同一条总线上。

项目 串口 CAN
常见信号线 TX / RX CANH / CANL
常见连接方式 点对点 多节点总线
抗干扰能力 一般 较强
多电机系统 布线较复杂 比较适合

现阶段需要掌握的内容

要使用 CAN 控制达妙电机，首先需要理解：

仲裁、显性位和隐性位、CRC、ACK、位填充、错误帧、终端电阻以及 CAN FD 等内容，可以在实际完成基础通信后继续学习。

简单总结，当前系统的工作过程就是：电脑通过 USB2CAN 将控制命令转换成 CAN 报文，经 CANH 和 CANL 发送给达妙电机；电机执行命令后，再把自身状态反馈给电脑。
