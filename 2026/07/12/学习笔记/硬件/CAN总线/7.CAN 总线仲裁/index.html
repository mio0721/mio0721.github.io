CAN 总线仲裁：多个设备同时发送时如何决定优先级

CAN 总线仲裁：多个设备同时发送时如何决定优先级

CAN 允许控制器、电机和传感器等多个节点共享同一条总线，因此可能出现多个节点同时准备发送报文的情况。

CAN 不依靠主控制器逐个点名，而是通过硬件仲裁决定当前由谁占用总线。仲裁失败的节点不会破坏获胜报文，而是在总线重新空闲后再次尝试发送。

什么是仲裁

仲裁对应英文 Arbitration，可以理解为多个节点同时发送时的优先级竞争。

两台设备会从帧开始位置同步发送，并在发送的同时监听总线电平。当某个节点发现总线上的实际值与自己发送的值不一致时，就能判断自己是否已经失去仲裁。

因此，在相同帧格式等条件下，数值更小的 CAN ID 通常拥有更高仲裁优先级。

实际比较规则还会受到标准帧、扩展帧和 RTR 等位的影响，因此“ID 越小优先级越高”是常用简化结论，但不是脱离帧格式后唯一的完整规则。

CAN 是广播式总线

总线上的节点都可以看到正在传输的报文。节点通过 CAN 控制器中的接收过滤器决定哪些报文交给上层程序处理。

过滤器可以减少 CPU 不必要的中断和解析工作，但它不会改变报文在物理总线上的广播特性。

相同 CAN ID 的风险

多电机系统中，不应让两个独立节点使用同一个 ID 发送不同内容。

如果两个节点同时发送完全相同的 ID，它们会一起通过仲裁。如果后续数据不同，节点可能检测到位错误并触发错误处理，导致报文无法正常完成。

因此协议设计应尽量保证：

  • 同一类发送源使用唯一且明确的 ID；
  • CAN_ID 和反馈 ID 不发生意外冲突；
  • 不同消息类型占用规划好的 ID 区间；
  • 高优先级 ID 留给真正需要低延迟的消息。

达妙电机中的仲裁

达妙电机和控制器都是 CAN 节点。电机可以发送状态反馈，控制器也可以发送控制帧。当多个报文同时准备发送时，同样由 CAN 控制器硬件参与仲裁。

优先级并不是越高越好

ID 越小虽然通常越容易优先发送，但不应该为了让某条消息“更快”就随意修改协议 ID。

如果高优先级节点持续大量发送，低优先级报文可能长时间等待。设计时需要综合考虑：

  • 控制指令和安全报文的时限；
  • 电机反馈频率；
  • 传感器数据量；
  • 报文长度；
  • 总线波特率；
  • 允许的最坏等待时间。

总线负载与控制周期

总线负载可以粗略理解为 CAN 总线有多大比例的时间正在传输报文。

仲裁过程总结

CAN 仲裁将优先级直接融入报文标识符，使高优先级消息可以在多节点系统中更快获得总线，同时又不破坏已经获胜的数据帧。
