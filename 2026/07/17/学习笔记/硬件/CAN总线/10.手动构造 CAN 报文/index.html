哪些字段由应用程序填写

普通 CAN API 通常要求应用程序设置：

  • 标准帧或扩展帧；
  • 数据帧或远程帧；
  • CAN ID；
  • DLC；
  • DATA。

SOF、仲裁过程、CRC、ACK、位填充和 EOF 等底层内容通常由 CAN 控制器或适配器完成，不需要应用程序逐 bit 生成。

用对照实验验证

手动发送前，可以先用普通“使能”按钮抓取标准报文，再在自定义发送区输入完全相同的 ID 和 DATA。

如果两次操作得到相同反馈，说明手动构造的帧与上位机自动生成的帧一致。

还可以在电机保持安全、随时可以失能的前提下验证：

  • 使用正确 DATA 但错误 ID，目标电机通常不会执行；
  • 使用正确 ID 但错误 DATA，电机不会把它识别成对应特殊命令；
  • 使用正确 ID 和 DATA，但错误波特率或帧格式，通信仍会失败。

这些实验只用于理解字段作用，不能使用可能产生未知动作的随机 DATA。

发送成功不等于执行成功

API 返回“发送成功”通常只表示报文已经交给 USB2CAN 或 CAN 控制器，不代表目标电机一定收到并执行。
