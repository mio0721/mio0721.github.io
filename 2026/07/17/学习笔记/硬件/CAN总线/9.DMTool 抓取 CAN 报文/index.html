使用 DMTool 抓取达妙电机 CAN 报文

前面已经从协议角度了解了 CAN ID、DLC、DATA，以及达妙电机的使能、失能和反馈帧。这一节使用 DMTool 的 CAN 分析功能观察真实报文，把上位机按钮和底层协议对应起来。

第一次实验只抓取使能和失能报文，不发送位置、速度或力矩命令。

实验前检查

开始前先固定电机并确认：

  • 电机与 USB2CAN 正常供电；
  • CANH 对 CANH、CANL 对 CANL；
  • 参考地和终端电阻符合设备接线要求；
  • USB2CAN 与电机的波特率一致；
  • 已知电机的 CAN_ID、Master ID 和当前控制模式。

不要直接假定 CAN_ID 一定是 0x01。应先从参数页面读取实际值。

控制帧和反馈帧

CAN 分析仪中可能同时出现大量报文，这是正常现象。除了上位机发出的控制帧，电机还可能周期发送反馈帧。

而：

可能是由 Master ID 相关规则组织的反馈帧，其中包含状态、电机编号、位置、速度、力矩和温度。

具体 ID 规则和字段格式应以当前型号和固件协议为准。

如何快速定位控制报文

可以使用对照法：

  1. 不执行任何操作，记录当前持续出现的 ID；
  2. 点击一次使能，搜索新出现的 ... FC 报文；
  3. 点击一次失能，搜索新出现的 ... FD 报文；
  4. 对比两次操作前后的时间戳、ID 和 DATA。

反馈数据会随着位置、速度和力矩变化，因此其 DATA 往往不是固定值。第一次抓包只需要先分清控制帧和反馈帧，不必立即人工解析每一条反馈。

总线占用率

多个电机同时进行高频控制和反馈时，总线占用率会增加。占用率过高会增加仲裁等待和报文延迟。

抓包时可以同时关注：

  • 每个 ID 的出现频率；
  • 单帧长度；
  • 是否存在大量重复发送；
  • 是否出现错误帧；
  • 总线占用率是否接近饱和。

推荐的首次操作流程

第一次做到这里就足够，不需要立即让电机运动。

如果抓不到报文，应依次检查分析仪是否开始接收、设备供电、USB2CAN 状态、CANH/CANL、波特率、CAN ID、控制模式和终端电阻。能发送但没有反馈时，还应检查 Master ID、接收过滤器和驱动器错误状态。

先用 DMTool 证明硬件链路和协议配置正确，再编写 Python 或 C++ 程序，可以显著缩小调试范围。
