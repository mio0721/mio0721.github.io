Docker 入门：Docker Compose、存储、网络与实际开发

当项目只有一个容器时，使用 docker run 并不复杂。但实际系统往往同时包含后端、数据库、缓存、消息队列和监控服务。如果分别维护多条启动命令，端口、网络、数据卷和环境变量很容易变得混乱。

Docker Compose 使用一个 YAML 文件描述整套服务，让多容器应用可以统一创建、启动、停止和查看日志。

Named Volume 与 Bind Mount

Docker 常见的持久化方式有两种。

Named Volume

优点是生命周期清晰，不依赖项目目录的具体位置；缺点是不能像普通项目文件那样直接浏览和编辑。

Bind Mount

Bind Mount 将宿主机真实目录挂载到容器中：

它适合源代码、配置文件和需要即时同步的开发目录。修改宿主机代码后，容器可以立即看到变化。

类型 管理者 常见用途

Bind Mount 可能覆盖镜像中目标路径原有的文件，挂载前应确认容器路径是否正确。

常见问题

容器是虚拟机吗

不是。容器更接近使用 Linux 隔离机制运行的一组进程，通常与其他容器共享宿主机内核。

删除容器会删除数据库吗

取决于数据保存位置。使用独立 Named Volume 时，删除容器通常不会删除 Volume；如果数据只在容器可写层中，删除容器就可能造成数据丢失。

Compose 是 Docker 吗

Compose 是组织和运行多个 Docker 服务的工具，底层仍由 Docker Engine 管理镜像、容器、数据卷和网络。

容器之间为什么不能使用 localhost

因为每个容器都有独立的网络环境。一个容器中的 localhost 只指向自己，访问另一个 Compose 服务时应使用其服务名。
